## Gap found

`spec/equiv/cells/stack-ops/C-L-arity` claimed the full 2DROP..TUCK band but
built one closed function per opcode, all at an empty stack (`n = 0`). Because
every guard is `n < K`, `K = 6` and `K = 2` are observationally identical at
`n = 0`: the wave16b audit (S2-2) was right that guard-threshold mutants
survive. Of the 55 (opcode, depth) faces the row needs inside the bounded leaf,
the old cell had 16 depth-0 underflow rows and was missing 39:

- **23 missing insufficient-depth rows** (every `1..K-1`):
  `2drop d1`, `2dup d1`, `3dup d1,d2`, `2over d1,d2,d3`, `2rot d1,d2,d3,d4,d5`,
  `2swap d1,d2,d3`, `nip d1`, `over d1`, `pick d1`, `roll d1`, `rot d1,d2`,
  `swap d1`, `tuck d1`.
- **16 missing boundary rows** (the smallest admitted depth `K`):
  `2drop d2`, `2dup d2`, `3dup d3`, `2over d4`, `2rot d6`, `2swap d4`,
  `ifdup d1`, `drop d1`, `dup d1`, `nip d2`, `over d2`, `pick d2`, `roll d2`,
  `rot d3`, `swap d2`, `tuck d2`.

`table.csv` records the split in its `old_cell` / `previously_missing` columns;
`src/check_table.py` fails the run if the leaves, `fns.txt` or the expected
observables drift from it.

## Work

Extended the same cell (no new row, no ledger edit) to a 55-row table: 39
underflow rows (every depth `0..K-1`) plus 16 boundary rows (depth `K`).

- Underflow rows: six **symbolic** seed bytes, expected `0x48`
  (`res=0`, `INVALID_STACK_OPERATION=18 << 2`). The proof therefore says the
  verdict is independent of element content.
- Boundary rows: uniform one-byte seed, expected `res=1 | post_depth<<8 |
  0x01` per live slot, where `post_depth` is the documented net depth of the
  Core case body (2DROP 0, 3DUP 6, 2ROT 6, PICK 2, ROLL 1, …). This catches a
  guard that is too strict, which no underflow row can see.
- C: line-cited transcription of each `if (stack.size() < K)` guard, plus net
  depth only at the boundary. L: the twin handler generated verbatim by
  `cells/_tools/mk_leaf.py`. Shared cell-local harness `src/arity_common.h`
  (always-inline observable, because the family `pack_vals` stays a call at
  `-O1` and alive-tv rejects it as an unknown libcall).

## Non-claims / remaining bounds

- The table is a bounded closed-witness enumeration: depth ≤ 6, one-byte
  elements, uniform seed, base sigversion, `flags=0`, `nOpCount=0`. Symbolic
  depth and depths above `K` other than the boundary are not claimed.
- Boundary rows claim only "no arity error at depth `K` plus the net depth";
  element semantics/order for these opcodes remain with the other E1/stack
  cells (`e1-stack/*`, `stack/C-L-*`, `stack-ops/C-L-ifdup`, `C-L-pick`).
- Budget-first ordering (an opcode-budget failure wins over the arity error)
  is out of scope here; `C-L-ifdup` and the budget cells carry it.
- The Lean side (`BitcoinProofs.AF.PDW79b.stepBody_*_depth`) already quantifies
  an arbitrary `st.stack.length < K`; no Lean change was needed.
- `spec/db/equiv-cells.yaml` was **not** edited (shared file): the SCR-074
  `gap_note` there still describes the old `partial` coverage and should be
  regenerated by the ledger integration step.
- The superseded empty-stack leaf under `cells/_tools/arity/` is left untouched
  (shared tooling path); this cell no longer runs it and its certificates do
  not reference it.
