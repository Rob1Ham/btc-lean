# exec-verify/C-L-p2sh-handoff — notes

## Design

Two functions, because SCR-005 has two distinguishable halves:

- `cell_p2sh_shape` is the 23-byte template predicate.  It is exact and
  unbounded: `IsPayToScriptHash` reads only `size`, `[0]`, `[1]`, `[22]`, so
  passing those four fields symbolically covers every possible script.  This
  is the one place in the exec-verify family where the shape test is *not* a
  declared input.
- `cell_p2sh_handoff` is the stack transfer.  The post-scriptSig stack is the
  input (depth 0..3, symbolic one-byte elements, Core's bottom-to-top order);
  the output is the stack the subscript EvalScript would start from, plus the
  popped redeem byte and a `restored` bit.

The L leg is where the cell earns its keep.  Lean's `Stack` is a list with
head = top (`stack[0]!`), while Core's `std::vector` has back = top.  The L
leg therefore builds Lean's `stackCopy = pubKeySerialized :: rest` head-first
from the Core-ordered inputs, destructures it, and reverses `rest` back to
bottom-to-top for the observable.  If the reversal were dropped, Alive2 would
report swapped items at depth 2-3.  C and L are not textual copies.

SAW checks both legs against the same Cryptol table (`saw/cell.cry`), which
states the handoff directly in Core order: top = `t{sn-1}`, prefix =
`t0..t{sn-2}`.

## The assert at 2074

`assert(!stack.empty())` fires only if the post-scriptSig stack was empty.  A
P2SH-shaped scriptPubKey (`OP_HASH160 <20> OP_EQUAL`) evaluated on an empty
stack fails with `INVALID_STACK_OPERATION` at 2034-2036, before the arm is
reached.  That argument lives in the scriptPubKey EvalScript, so this cell
does not claim it: `sn = 0` is the declared out-of-model marker 3 in both
legs, excluded from the claim.  Lean totalizes the same arm as
`.fail .unknownError` (`p2shInner`, the `| []` match arm, with the comment
"Core: assert(!stack.empty()) — unreachable").

## Bounds

| input | bound | why |
|---|---|---|
| captured stack depth | 0..3 | harness; the handoff is a top/pop/prefix, no loop |
| element size | 1 byte | only the redeem byte is observable here; the serialized script is opaque |
| shape fields | full 6-bit length, 8-bit bytes | exact predicate |

The size-1 element bound does not weaken the handoff: elements are moved
whole and never inspected.  It does mean the cell does not prove that
`CScript pubKey2(begin,end)` copies *all* bytes of a multi-byte element —
that construction is the identity on the element's byte vector and is cited,
not proved.

## Mutation proposals (not executed)

1. Drop the `rest` reversal in the L leg.  Expected Alive2 counterexample at
   `sn = 3, t0 ≠ t1`; SAW failure of `cell_p2sh_handoff`.
2. Replace the packed prefix with the post-scriptPubKey stack (i.e. forget
   the `swap`).  Expected counterexample wherever the two stacks differ;
   SAW failure.
3. Make `cell_p2sh_shape` accept `len == 23 ∧ b0 == 0xa9` only (drop the
   0x14/0x87 conjuncts).  Expected Alive2 counterexample at `b_last = 0x00`;
   SAW failure of `cell_p2sh_shape`.

The unmutated cell is green first.
