# exec-verify/C-L-failure-propagation — notes

## Design

`VerifyScript` has exactly five calls whose failure returns false:

| site | line | callee | arm |
|---|---|---|---|
| 1 | 2029-2031 | `EvalScript(scriptSig)` | always |
| 2 | 2034-2036 | `EvalScript(scriptPubKey)` | always |
| 3 | 2052-2054 | `VerifyWitnessProgram(is_p2sh=false)` | bare witness program |
| 4 | 2080-2082 | `EvalScript(pubKey2)` | P2SH arm |
| 5 | 2097-2099 | `VerifyWitnessProgram(is_p2sh=true)` | P2SH witness program |

Each is `if (!call(...)) return false;` with the callee's `serror` already
set.  The cell takes each callee as the pair `(ok, err)` and proves the four
properties that make the wiring correct: failure ⇒ result 0, the callee's
error is preserved, the first failure in Core's order wins (no later site
runs), and an unreached site cannot invalidate.

The three conditional sites are gated by declared `act3/act4/act5` booleans.
Site 5 is gated by `act4 ∧ act5` because it is inside the P2SH arm and inside
the redeemScript's witness-program test.  The activity predicates themselves
are inputs — proving them is the tail cell's job (SCR-011/SCR-013 etc.).

The L leg is a reviewed transliteration of `verifyScriptFull`'s `match`
chain.  It is written as nested conditional expressions (Lean `match` is an
expression), so the IR is a select tree, while the C leg is early-return
branches.  `p2shInner` flattens into sites 4 and 5 because that is where its
two failure sources live in `verifyScriptFull`.

`VerifyOutcome.unjudged` is not modelled: SCR-017 is "failure ⇒ invalid", and
`.unjudged` is neither failure nor success.  It is recorded as outside the
cell in `spec.md`.

## Why this is a full row despite the abstraction

The row quantifies over *call failures*, not over the callees' internals.  A
cell that tried to model `EvalScript` would be a different, much larger row
(E5).  With `(ok, err)` symbolic, the proof covers every possible failure
outcome of every site, including error ordinals the callee might emit, so the
implication is proved as stated.

## Mutation proposals (not executed)

1. Drop the site-2 return in the L leg.  Expected Alive2 counterexample at
   `ok2 = 0`; SAW failure.
2. Return `(0, 0, site)` instead of `(0, err_site, site)`.  Expected
   counterexample for any nonzero callee error; SAW failure.
3. Gate site 5 only on `act5` (forget that it lives inside the P2SH arm).
   Expected counterexample at `act4 = 0, act5 = 1, ok5 = 0`; SAW failure.

The unmutated cell is green first.
