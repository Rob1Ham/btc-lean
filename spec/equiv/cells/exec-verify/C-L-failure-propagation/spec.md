# exec-verify/C-L-failure-propagation

The five failure returns in `VerifyScript`: every failed `EvalScript` /
`VerifyWitnessProgram` call invalidates the input, preserves the callee's
error, and stops the function.

## The region

```c
// interpreter.cpp:2029-2031
if (!EvalScript(stack, scriptSig, flags, checker, SigVersion::BASE, serror))
    // serror is set
    return false;
// 2034-2036
if (!EvalScript(stack, scriptPubKey, flags, checker, SigVersion::BASE, serror))
    return false;
// ...
// 2052-2054 (bare witness program)
if (!VerifyWitnessProgram(*witness, witnessversion, witnessprogram, flags,
                          checker, serror, /*is_p2sh=*/false))
    return false;
// ...
// 2080-2082 (P2SH subscript)
if (!EvalScript(stack, pubKey2, flags, checker, SigVersion::BASE, serror))
    return false;
// 2097-2099 (P2SH witness program)
if (!VerifyWitnessProgram(*witness, witnessversion, witnessprogram, flags,
                          checker, serror, /*is_p2sh=*/true))
    return false;
```

## What is proved

- **No swallow**: a failure at any reached site makes the result 0 (invalid).
- **No relabel**: the error returned is the callee's ordinal, unchanged.
- **Short-circuit**: only the first failing site in Core's order is reported;
  later sites do not run.
- **Gating**: a site whose arm is not entered cannot invalidate the input.

These are the four content claims of SCR-017 at the wiring level.  The cell is
deliberately not a model of the callees: `ok`/`err` are symbolic inputs, so
the proof covers every outcome they could produce.

## What is not proved

- The callees themselves (`EvalScript`, `VerifyWitnessProgram`) — E5
  residual; a real execution would also need the dispatch, the opcode limit,
  and the ECDSA/hash premises.
- The arm-activity predicates (tail cell, `C-L-verifyscript-tail`).
- Lean's `.unjudged` outcome, which is not "failure ⇒ invalid".
