# exec-verify/C-L-w32-flags-combo

SCR-014, the VerifyScript flag-combination constraint. The row is the
`flagsComboOk` predicate that Core encodes as two `assert()`s
(interpreter.cpp:2113-2114 and :2124).

## What is proved

For **every** 64-bit `script_verify_flags` word and **both** values of the
CLEANSTACK policy bit, the C slice and the Lean transliteration return the
same 0/1:

```
(!cleanstack || (P2SH && WITNESS)) && (!WITNESS || P2SH)
```

* Alive2 v20.0: symbolic C-vs-L comparison, `1 correct transformations`,
  `0 failed-to-prove`, no errors.
* SAW 1.6: both modules verified against `saw/spec.cry` (the independent
  `flagsComboOk` expression), two `Proof succeeded!`.

## Exact commands

```sh
spec/equiv/cells/exec-verify/C-L-w32-flags-combo/alive2/run.sh
spec/equiv/cells/exec-verify/C-L-w32-flags-combo/saw/run.sh

sha256sum -c spec/equiv/cells/exec-verify/C-L-w32-flags-combo/alive2/certificate.sha256
sha256sum -c spec/equiv/cells/exec-verify/C-L-w32-flags-combo/saw/certificate.sha256
```

## Scope and trust note

The C side is the *predicate* the asserts encode, not the assert statement
itself. Core's `assert` has no defined release-mode (NDEBUG) observable
behaviour on a violating flag word, so nothing is claimed about that case;
what is proved is that the well-formedness predicate is exactly Lean's
`flagsComboOk`, i.e. WITNESS implies P2SH (and CLEANSTACK implies both).

The L side is a reviewed hand transliteration of
`spec/core/Bitcoin/Interpreter/Rules.lean:48-50`; the Activation module has
no twin generated by `twin/gen.py`, so the README section 3 "reviewed
transliteration" fallback applies. The cell does not touch VerifyScript's
body, scripts, transactions or heights.

The CLEANSTACK arm is part of the same source site and the same Lean
definition, so it is included in the predicate; SCR-009 (a separate ledger
row) is deliberately **not** claimed by this cell.
