# exec-verify/C-L-verifyscript-tail — notes

## Design

The cell is the `VerifyScript` tail: everything from the first
post-`EvalScript` check at `interpreter.cpp:2037` to `set_success` at 2131.
It starts after both `EvalScript` calls and therefore takes their outcome as
inputs (stack depth, top element, witness counts, shapes).  The three callees
whose *failure* is part of the row set (`EvalScript` of the P2SH subscript,
both `VerifyWitnessProgram` calls) are declared outcome inputs; their failure
wiring is `C-L-failure-propagation`.

Two independent encodings:

- C leg: a line-cited excerpt in Core's control-flow order, including
  `CastToBool` (interpreter.cpp:46-59) and the single-push comparison
  (2092, `CScript::operator<<` canonical encoding).
- L leg: a reviewed transliteration of `p2shInner` + `verifyScriptFull`
  (`Defs.lean:1328-1455`), written in Lean's *shape*: `hadWitness` is not a
  variable, it is recomputed from the two witness-arm predicates; the final
  depth is selected by the same three-way case.  The transliteration keeps
  Lean's `p2shInner`-before-tail ordering, which is what makes the
  `42`-before-`30`/`43` precedence non-trivial.

SAW checks both legs against `saw/cell.cry`, a condition table read off the
row table in `spec.md`.  The Cryptol table is *not* a transliteration of
either C or Lean: it is the shortest statement of the precedence order
(41 → 42 → 30 → 43 → pass).

A Cryptol bug found and fixed during development is worth recording because
it was a real spec bug, not a harness bug: the first version of `vs_tail`
wrote `m1 w && m1 spkw && m2 sign` as a Boolean condition.  In Cryptol `&&`
on `[64]` is bitwise AND, so `1 && 1 && 1` is a *number* (1) and the
`if` accepted it only accidentally; with `sign = 0` the whole expression
became `0`, which Cryptol then requires to be `Bit`.  The committed spec uses
explicit `!= zero` / `== zero` conjuncts everywhere.

## The two invariants

- `hadWitness` is set by the bare arm and by the P2SH-wrapped arm, and by
  nothing else.  `C-L-verifyscript-tail` proves the SCR-013 tail
  `!hadWitness && !witness->IsNull()` for every witness item count and both
  arms.
- the depth CLEANSTACK sees is `resize(1)` after a consumed witness program,
  the subscript result on plain P2SH, and the post-scriptPubKey depth
  otherwise.  SCR-008 is exactly `!= 1` on that depth; the cell proves the
  selection and the check in Core's order.

## Disclosed L-leg deviation

Core resizes the stack to 1 (`interpreter.cpp:2057`, `2102`).  Lean
*recomputes* the length for the plain-P2SH arm (`finalLen`) and writes the
constant 1 for the witness arms.  On the reachable P2SH-witness domain the
42 guard forces `scriptSig == push(redeemScript)`, so `stackCopy` has one
element, the subscript `OP_n <program>` leaves exactly one item, and Lean's
recomputation equals Core's resize.  This cell uses the constant 1 and states
the premise; the general recomputation (arbitrary redeem script on the
witness arm) is not modelled.  This is the one place the L leg follows Core
rather than Lean's literal definition, and it is called out in `spec.md`
under `trust_note`.

## Bounds

| input | bound | why exact |
|---|---|---|
| post-eval stack depth | 0..3 | harness; the tail has no loop, depth only feeds `== 1` |
| top element | 0 or 1 byte | `CastToBool` on >1 byte is not exercised; 1 byte covers true/false/-0 |
| scriptSig size | 0..3 | only `== 0` and the single-push comparison read it |
| witness items | 0..3 | only `IsNull()` (i.e. `== 0`) is read |
| redeemScript length | 0..2 | single-byte push encoding (`script.h:408-423`) |

These are input domains, not weakened checks: no predicate in the tail is
approximated.

## Build and tools

```text
clang++-20 (Ubuntu clang version 20.1.2)
llvm-extract/llvm-dis 20.1.2
alive-tv 20.0 (LLVM 20.1.2 build)
SAW 1.6 (68eed5f, release-1.6), bundled z3
```

`build/` is generated by `findings/wave16/01-exec-verify/tools/lib.sh`
(`ev_build_pair`): `-O1 -fno-strict-aliasing -fno-discard-value-names`,
`-c -emit-llvm`, then `llvm-extract --func=<fn> --recursive` per function so
each Alive2 comparison sees exactly one exported function per module.
`build/` is git-ignored (`spec/equiv/.gitignore`); both certificates include
the generated `.ll`/`.bc` hashes, so `sha256sum -c` is meaningful after a
cell run.

SAW is run with cwd = `build/`, so `llvm_load_module` uses
`"../build/c_leaf.bc"` relative to `saw/cell.saw`.

## Mutation proposals (not executed)

1. Drop the `!had` conjunct of the SCR-013 tail.  Expected Alive2
   counterexample at `witness=1, spk_wit=1, sig_n=0, wit_n=1` (C passes,
   L returns 43); SAW failure on `cell_vs_tail`.
2. Move the CLEANSTACK check before the P2SH arm.  Expected counterexample
   where both 42 and 30 are reachable: C returns 30 first only if depth != 1,
   while the mutant would return 30 before evaluating the 42 guard.
3. Drop the `bare_wit` disjunct from Lean's `B` predicate in the P2SH tail
   (SCR-013's `A ∨ B`); expected failure on the bare-witness-with-non-empty
   witness combination.

The unmutated cell is green first, as required for a usable mutation.
