# e2-numeric/within-boundary

SCR-089 (`min ≤ x < max`, `OP_WITHIN`), implemented as a bounded op cell
with **both tools green symbolically** over all one-byte operand triples.

## L leg

`src/l_leaf.cpp` includes `build/twin_ops.h`, generated by
`cells/_tools/mk_leaf.py --ops OP_WITHIN --max-depth 4 --max-elem 2`.
The `op_OP_WITHIN` body is copied verbatim from `twin/ops_ir.py`
(`lean Defs.lean:1019-1027`). Only `l_init`, the three pushes, dispatch, and
the finish/pack harness are cell code.

## Symbolic claim

The entry point is `uint64_t cell_within(uint8_t av, uint8_t bv, uint8_t cv)`.
Each argument is one raw element byte (the stack is `[x, min, max]`).

- Alive2: `alive-tv build/c_cell_within.ll build/l_cell_within.ll` proves
  C and L agree for every i8 triple.
- SAW: `src/cell.saw` verifies **both** modules against the independent
  Cryptol predicate in `src/cell.cry`, for every i8 `a, b, c`:
  `within a b c = (decode1 b <=$ decode1 a) && (decode1 a <$ decode1 c)`.
  The postcondition is the packed observable from `e2_common.h`.

This is 2^24 operand triples. It is the whole rule for one-byte operands,
but not for 2–4 byte operands: those belong to the width-cap rows
SCR-079/SCR-080 and are not exercised here. `scr_row_coverage` in `spec.md`
records that limit.

## Notes and limits

- The packed observable canonicalises a zero-length element to value 0.
  Core's `vchFalse` is the empty vector; without this, a stale slot byte
  (the pre-image of the popped operand) would leak into the comparison and
  cause a spurious Alive2 mismatch. This is an observable-encoding decision,
  applied identically to C and L; it does not change op semantics.
- The C slice fixes operand length to 1, so `CScriptNum`'s width guard is
  statically discharged (1 ≤ 4). A symbolic 2–4 byte cell would need a
  wider `BStack` and a faithful `CScriptNum` decode; the twin's
  `decode_num` itself caps at 2 bytes (see `mk_leaf.py`), so that is a
  separate E2 gap, not this cell.
- No Core patch is used (`patches: none`).
- Mutation relevance: M-E2-004 (`OP_WITHIN` max boundary `<=` instead of
  `<`, site T+C) is expected to make `cells/e2-numeric/within-boundary`
  non-green. A twin-only flip is caught by Alive2 (C vs L) and by the SAW
  predicate; a same-direction flip in both C and L is caught by SAW, not by
  Alive2. The mutation was **not** executed here; see
  `findings/e2/report.md`.
