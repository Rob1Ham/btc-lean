# limits/C-L-scr-040-loop-fold

SCR-040: the BIP342 tapscript validation-weight seed,
`GetSerializeSize(witness.stack) + VALIDATION_WEIGHT_OFFSET`, with the
element loop-to-fold bridge **proved for an arbitrary item count**.

New cell only.  No shared proof, pin, contract, ledger, results, docs or twin
file is edited; no Core patch is used.

## Legs

- `src/c_leaf.cpp`: the loop shape.  `cg_vector_ser` writes
  `CompactSize(n_items)`, then iterates `i = 0..7` with `if (i < n_items)`,
  calling `cg_basic_byte_ser` on each element and threading one accumulator.
  `cg_basic_byte_ser` is `cs(len)` followed by a write of `len` bytes (the
  `!v.empty()` guard is a no-op for the byte count; it is proved in Lean and
  SAW, so the IR omits the branch to keep Alive2 tractable).
- `src/l_leaf.cpp`: the live model's shape, `CompactSize(n) +
  foldl (acc + CompactSize(len) + len) 0 lens` (as an unrolled loop at IR
  level, per-count instantiations for Alive2).
- `src/lean/LoopToFold.lean`: the cell-local operational-loop model and the
  arbitrary-count proof, plus kernel `decide` checks that the embedded source
  literals are the pinned text and that the printed ASTs match them.

## Proofs actually run

`src/cell.saw` is generated by `src/gen_cell_saw.py`:

- 40 `llvm_verify` successes: 2 scalar functions x 2 legs (4), plus 9 counts
  x 2 functions (`cell_vector_ser`, `cell_seed`) x 2 legs (36).  Counts are
  `0..8`; all eight item lengths are symbolic 32-bit values in every case.
- 6 `prove_print` lemmas (9-byte branch iff `n > 0xffffffff`; no 32-bit length
  takes it; item term <= 523 for len <= 520; 8-item seed <= 4237; empty seed
  = 51; seed = vector_size + 50).

Alive2 (`src/normalize_alive2.py` + `alive2/run.sh`):

- `cell_compact_size_size` (full 64-bit) and `cell_basic_byte_ser`
  (all 32-bit lengths, acc in 0..2^62): C = L.
- `cell_vector_ser_k` and `cell_seed_k` for every `k = 0..8`, all item
  lengths symbolic: C = L (18 functions, 18 comparisons).
- The symbolic-count `cell_vector_ser`/`cell_seed` are **not** in the Alive2
  set: Alive2 v20 times out on their 2^8 unrolled guard paths even after
  metadata normalisation.  SAW checks the same functions with a symbolic
  count `<= 8`; the arbitrary count is the Lean theorem.

Lean (`lean/run.sh`):

- `lake build Bitcoin` (zero-dependency core model), then
  `lake env lean src/lean/LoopToFold.lean`.
- `src/extract_pinned.py --check` re-reads the pinned Core tree, verifies
  `git rev-parse HEAD = cce32b168...`, checks the three cited file sha256s,
  and compares all eight embedded literals with a fresh extraction.
- `runLoop_eq_fold` and `seed_eq_validationWeightInit` have axioms
  `[propext, Quot.sound]`; no `sorryAx`.  The `decide`-checked pinned-text
  theorems additionally use `Classical.choice` (from `String` decidable
  equality), never `native_decide`.

## Codegen metadata normalisation (honest scope)

`src/build_cell.sh` is the shared limits recipe plus `-fwrapv`; both legs use
the same flags.  `src/normalize_alive2.py` removes, from **both** legs:

- `nocapture`, `readonly`, `writeonly`, `memory(...)` — caller-contract ABI
  hints Alive2 v20 cannot parse;
- `nsw`/`nuw` — overflow flags clang infers on `add`/`sub`/`mul`.

The overflow flags are true on this cell's domain (`uint32_t` item lengths,
at most 8 items, 64-bit accumulator), but Alive2 case-splits the flagged
3+-item bitvector queries and times out; without the flags the same functions
verify in under a second.  Removing them compares the wrap-around semantics
of identical arithmetic; because both legs get the identical transform and
the flags are true on the stated domain, the unflagged equality implies the
flagged equality there.  SAW checks the arithmetic as total 64-bit
bitvectors.  No instruction, operand, type or control-flow edge is changed.
The prepared IR is what `alive2/certificate.sha256` hashes.

## Limits

- The Lean bridge is a source-level refinement over a formalised fragment.
  The residual premise is the fragment semantics (range-for over a vector,
  `size_t` accumulation, SizeComputer seek/write) and the pin-text-to-AST
  transcription.  It is **not** the former prose premise
  `GetSerializeSize(loop) = foldl step`, which is now a theorem.
- No whole-`VerifyWitnessProgram` proof; only the seed assignment and the
  serializer it calls are sliced.  Annex/chunk context above the seed is out
  of cell.  Composition with the shared
  `validationWeightInit_eq_encoder` gives the actual encoder length + 50.
- Item bytes are abstracted to lengths, exactly as `GetSerializeSize` sees
  them.
- The 9-byte CompactSize branch is unreachable for a 32-bit item length; it
  is still implemented and proved over the full 64-bit domain.
