# Wave-32 exec-verify cell tooling (`w32/`)

Shared harness for the wave-32 SCR-014..017 cells. It is **not** engine code
and not part of the trust base for a semantics claim.

| File | Purpose |
|---|---|
| `w32_common.h` | Flag-bit values, mainnet heights, the two exception hashes, error ordinals — each line-cited to the pinned tree. |
| `c_flags.cpp` | C legs: line-cited slices of `VerifyScript` / `GetBlockScriptFlags` at `cce32b168`. |
| `l_flags.cpp` | L legs: reviewed hand transliterations of the Lean `Activation`/`Rules`/`Defs` definitions (record + Option representation). |
| `build_leaf.sh` | Compiles both legs with clang-20 `-O1 -fno-strict-aliasing` and extracts every function in the cell's `manifest.txt`. |
| `run_alive2.sh` | Symbolic C-vs-L compare per manifest function; writes `alive2/result.txt` + certificate. |
| `run_saw.sh` | Runs the cell's checked-in `saw/spec.saw` (against `saw/spec.cry`) and requires one `Proof succeeded!` per function per leg. |

Every cell has:

```
exec-verify/C-L-w32-<slug>/
  spec.md          # contract hash, pre/postcondition, directions, scr_rows
  manifest.txt     # one function name per line
  notes.md
  alive2/{run.sh,result.txt,certificate.sha256}
  saw/{run.sh,spec.cry,spec.saw,result.txt,certificate.sha256}
  build/           # regenerated by the runners; gitignored
```

Certificates are ROOT-relative, so verify them from the repository root:

```sh
sha256sum -c spec/equiv/cells/exec-verify/C-L-w32-<slug>/alive2/certificate.sha256
```

## Toolchain

* clang/clang++ 20.1.2, LLVM 20.1.2 (`llvm-extract`, `llvm-dis`)
* Alive2 v20.0 (`/usr/local/bin/alive-tv`)
* SAW 1.6 (`/opt/equiv-tools/saw-1.6/bin/saw`, provers `abc`/`z3`)

## Scope limits

* Symbolic proofs are over the scalar function domains stated in each
  `spec.md`; they are not whole-`VerifyScript` proofs and not node
  validation.
* The C legs are source-excerpt slices, not compiled Core translation units;
  Core headers are not included, so the cell's constants are transcriptions
  (documented in `w32_common.h`).
* The L legs are reviewed hand transliterations, not `twin/gen.py` output;
  `spec/equiv/README.md` section 3 labels that link.
* SCR-017's five engine calls are abstracted to their outcomes (partial row;
  see that cell's notes).
