# Cell `C-L-cms-tapscript-ban`

## What is proved

`cell_cms_tapscript_ban(sigversion, opcode, stackSize, nKeysIn, nSigsIn)` is a
total pure function.  The oracle (`saw/model.cry`) returns ordinal 50 exactly
when `sigversion == 2`, and otherwise walks the same front matter as
`C-L-cms-layout-sym` (without the opCount arm, which has no input here).  The
ban is the *first* test, so a stack that would otherwise underflow or a count
that would otherwise be out of range still reports 50.

The non-tapscript half is part of the observable, so "reject everything" is
not a valid implementation: BASE and WITNESS_V0 must reach the normal
decisions.

## Why `full`

SCR-121's summary is "TAPSCRIPT_CHECKMULTISIG"; the cell covers both the
positive (tapscript -> ordinal 50) and the negative (BASE/WITNESS_V0 not
banned) direction for every 32-bit input, with the ban's precedence over the
arity/range checks observable in the same return.

## Limits

- The opcode word is not distinguished (Core's ban is shared by 0xae/0xaf).
- Non-tapscript front matter here omits the opCount arm (no input); see
  `C-L-cms-layout-sym` for that arm.
- The post-ban verification loop is out of scope (other cells).
