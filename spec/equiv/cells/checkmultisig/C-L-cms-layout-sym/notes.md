## Reproduce

From the repository root:

```bash
bash spec/equiv/cells/checkmultisig/C-L-cms-layout-sym/alive2/run.sh
bash spec/equiv/cells/checkmultisig/C-L-cms-layout-sym/saw/run.sh
sha256sum -c spec/equiv/cells/checkmultisig/C-L-cms-layout-sym/alive2/certificate.sha256
sha256sum -c spec/equiv/cells/checkmultisig/C-L-cms-layout-sym/saw/certificate.sha256
```

Both runners build from `src/{c,l}_cms_layout.cpp` via
`../_shared/build_ir.sh`; nothing is fetched.  The SAW runner links the shared
family stub (`_shared/checker_stub.cpp`, case 0) into both modules even though
this cell never calls it, so every cell in the family has the same build shape.

## Design

- C leg: line-cited slice of the CHECKMULTISIG front matter
  (`interpreter.cpp:1118-1146`), specialized to a decision function.  The
  tapscript ban is excluded by domain (it is the separate SCR-121 cell).
- L leg: reviewed transliteration of the Lean `checkMultiSig` front matter
  (`Defs.lean:1071-1096`), not generated by `twin/gen.py`.
- Observable: status (3 bits) + nKeys + nSigs + ikey2 + isig, so the two
  derived cursor positions are part of the proof, not just the outcome.
- Oracle: `saw/model.cry` encodes signed int32 comparisons by biasing into
  `[64]`; every literal is written at full width (Cryptol 3.6 does not widen
  literals).

## Limits

- `decodeNum` is outside the cell: the inputs are already-decoded int32
  counts (precondition).  MINIMALDATA is off.
- `opCount` is an input, not a running total across opcodes.
- No checker call is reached, so the same-crypto premise is vacuous.
- `grep -c "Proof succeeded"` counts lines; the status line reports
  2 proofs for 1 case (one per leg).
