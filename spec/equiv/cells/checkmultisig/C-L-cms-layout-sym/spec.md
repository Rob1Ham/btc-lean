# Cell `C-L-cms-layout-sym`

## What is proved

`cell_cms_layout(nKeysIn, nSigsIn, stackSize, opCount)` is a total pure
function on four fully symbolic 32-bit inputs.  Alive2 proves the two IR
functions equivalent in both directions; SAW proves each leg against an
independent Cryptol oracle (`saw/model.cry`) written from the Core lines and
the Lean front matter.  The oracle encodes signed comparisons by biasing the
32-bit value into `[64]` (`0x80000000 + zext x`), so `nKeys < 0` and
`nSigs > nKeys` are exercised for the whole two's-complement range.

| Outcome | Core line | Status |
|---|---|---|
| `depth < 1` | 1122-1124 | 3 underflow |
| `nKeys < 0 \|\| nKeys > 20` | 1127-1128 | 1 pubkey_count |
| `opCount + nKeys > 201` | 1129-1131 | 2 op_count |
| `depth < nKeys + 2` | 1136-1138 | 3 underflow |
| `nSigs < 0 \|\| nSigs > nKeys` | 1140-1142 | 4 sig_count |
| `depth < nKeys + nSigs + 3` | 1143-1146 | 3 underflow |
| otherwise | 1134, 1143 | 0 ok, ikey2/isig |

## Why `full`

SCR-114's summary is exactly "nKeys∈[0,20], nSigs∈[0,nKeys], depth checks";
every arm and every precedence transition is exercised symbolically, and the
derived `ikey2`/`isig` are part of the observable so a wrong decode cannot hide
behind a common status.  The only precondition is that the count elements have
already been decoded — `decodeNum` is not part of this row, and the row's
`core_ref` ends at the layout decision, not at `cmsLoop`.

## Limits

- This cell does not run the verification loop; matching order is
  `C-L-cms-order-unroll` (partial) and the encoding gates are
  `C-L-cms-enc-loop` (partial).
- `opCount` is an input, not a running total across the script; the
  carry-in value is part of the precondition.
