# Cell `C-L-cms-fad-probe`

## What is proved

`cell_cms_fad(nsigs, sigversion, constflag, script)` models the pre-loop
deletion fold and then runs the verification loop as a *probe*: it records the
scriptCode seen by each checker call.  Alive2 compares C and L with both the
checker and FindAndDelete uninterpreted; SAW checks both legs against the
Cryptol oracle under checker false (one body) and true (two bodies), with a
concrete FindAndDelete stub.

The trace distinguishes:

| Path | Observable |
|---|---|
| BASE, 2 sigs, no found, checker true | applied=2, calls=2, call0=call1=final |
| BASE, found on sig 0, constflag=0 | applied=2, final advanced, checker sees it |
| BASE, found on sig 0, constflag=1 | result=3, err=54, calls=0 (latch before the loop) |
| WITNESS_V0 | applied=0, script unchanged |

## Why `partial`

- FindAndDelete is a shared abstract symbol: the deletion algorithm is not
  proved (SCR-098/INV-056 owns it).
- The fold and the probe loop are unrolled to nSigs = nKeys <= 2; the row's
  domain allows 20.  Larger counts are rejected by the guard.

## Limits

- nKeys = nSigs by construction; the loop's matching policy is not this
  row (SCR-116).
- Script content is a 32-bit seam identity, not a byte array; the concrete
  byte-walk is deliberately out of scope.
- The checker contributes the usual same-crypto premise.
