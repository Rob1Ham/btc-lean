# Cell `C-L-cms-tail-sym`

## What is proved

`cell_cms_tail(nkeys, nsigs, extra, fsuccess, nulldummy, wire, dummyLen,
dummyBytes)` is total and fully symbolic.  The oracle (`saw/model.cry`) is
written from the Core tail and the Lean `cmsCleanup`/`checkMultiSig` equations
and packs the same top-three elements.  Alive2 compares the two leg IRs in
both directions; SAW checks both legs against the oracle in the same build.

| Row | Claim | How the cell exercises it |
|---|---|---|
| SCR-118 | extra item consumed unchecked | `dummyBytes` is a free 32-bit input absent from every RHS; the item is popped for all lengths (including non-empty dummies with NULLDUMMY off) |
| SCR-119 | dummy must be empty post-SegWit | `nulldummy != 0 && dummyLen != 0` -> ordinal 28; length 0 passes |
| SCR-120 | false -> CHECKMULTISIGVERIFY error | `wire == 0xaf && fsuccess == 0` -> ordinal 13 |

## Why `full`

All three rows are general over the counts (0..2^32 arithmetic, not a 1-of-1
witness), over every fSuccess value, over both opcodes, and over empty and
non-empty dummies; the observable exposes the surviving stack shape so a
compensating error cannot hide.  This is a full proof of the *tail*, not of the
loop that produces fSuccess.

## Limits

- `fSuccess` is an input: the cell does not prove that the loop produces it.
- NULLFAIL (SCR-110) is off by domain; a non-empty dummy *with NULLFAIL on* is
  not this cell.
- The stack depth field is six bits (harness), wrapping at 64.
