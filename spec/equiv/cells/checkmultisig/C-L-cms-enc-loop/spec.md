# Cell `C-L-cms-enc-loop`

## What is proved

`cell_cms_enc(nkeys, nsigs)` returns, for up to two loop bodies, which gate was
evaluated for which pair, which one fired, whether the checker was reached and
what it returned.  Alive2 compares the two leg IRs with the checker and both
validators uninterpreted; SAW checks both legs against the Cryptol oracle
under six stub instances: 0/1/2 checker false/true/diagonal with gates
accepting, 5 signature gate rejects every signature, 6 checker diagonal with
the signature gate rejecting only signature index 1, 7 pubkey gate rejects
everything.

Case 6 is the per-pair witness: body 0 passes both gates, calls the checker
and matches; body 1's signature gate fires with SIG_DER=24 and the checker is
not called — visible in the packed trace as `entered=3, sigRej=2,
chkCalled=1, chkTrue=1, err=24`.

## Why `partial`

Two gaps, both stated in the front matter:

1. The loop is unrolled twice (`nKeys <= 2`); the row's domain allows 20.
   Larger counts are rejected by the cell guard.
2. The encoding validators are abstract seam symbols and `flags` is fixed at
   0.  The cell proves the *call sites, order, precedence and error/latch
   behaviour*, not that DERSIG/LOW_S/STRICTENC accept or reject a given byte
   string.

## Limits

- nKeys <= 2, nSigs <= nKeys; only two bodies.
- FindAndDelete (SCR-115) and the loop's matching order (SCR-116) are separate
  cells; this cell shares their element convention.
- Same-crypto premise for the checker; the validators are a further shared
  abstraction.
