# Cell `C-L-cms-order-unroll`

## What is proved

`cell_cms_order(nkeys, nsigs)` returns the verification loop's trace for
`nkeys <= 4` and `nsigs <= nkeys`.  Alive2 proves C ≡ L with the checker
uninterpreted (all behaviours at once); SAW checks both legs against the
Cryptol oracle under five concrete match relations.  The observable is the
trace, so "right pairs but wrong order", "checks after the early exit" and
"advances the signature without a match" are all caught even when fSuccess
coincides.

## Why `partial`

Core's bound is `MAX_PUBKEYS_PER_MULTISIG = 20` (interpreter.cpp:1127) and
`cmsLoop` runs at most nKeys bodies.  This cell unrolls 4.  The missing piece
is the 16-key tail of the unroll (or a loop-invariant proof, which Alive2
cannot do and which SAW would need as an `llvm_loop` spec).  nKeys > 4 is
rejected by the cell guard, so nothing outside the unroll is silently claimed.

## Limits

- nSigs <= nKeys and nKeys <= 4; larger counts are out of domain.
- Encoding gates (SCR-117) are off here; FindAndDelete (SCR-115) is a
  separate cell.
- Element encodings are one-byte cells of the seam encoding; the checker is
  abstract (same-crypto premise).
