## Why this shape

The withdrawn row had two separate gaps: the old cell proved NOP-ness only for
`OP_NOP`/`OP_NOP1`/`OP_NOP4..10`, and its observable was a fixed packed
constant over a closed witness.  Here:

1. **The right wires.** The functions dispatch 0xb1 and 0xb2, not the
   upgradable NOP wires.
2. **Symbolic, not a closed witness.** Every input that the branch could
   disturb is symbolic: stack depth (0..3), the top byte (all 256 values) and
   the incoming op-count (0..200).  Alive2 proves C ≡ L over the whole
   product; SAW proves each leg against a separate Cryptol predicate.
3. **The NOP claim has a state.** The observable is (result, error, depth,
   top byte, opCount), so "plain NOP" is proved as *state invariance*, not as
   a single canned return value.  This matches the row's Lean face
   `stepBody_cltv_csv_noflag_nop` (PDW73.lean:31-47), whose conclusion is
   `.ok { st with opCount := st.opCount + 1 }`.
4. **Flag-on contrast.** The same inputs with the activation bit set: an empty
   stack now returns `INVALID_STACK_OPERATION` (18) instead of continuing.
   That is the stack guard (`:539-540`, `:578-579`) becoming reachable, which
   is exactly what "pre-activation" means.

## Non-vacuity (mutants, executed but not committed)

Run in a scratch copy of `src/`:

| mutant | Alive2 result |
|---|---|
| L flag-off returns `INVALID_STACK_OPERATION` instead of continuing | counterexample at depth 0: C `0x200001`, L `0x200048` |
| L op-count bump `+1` → `+2` | counterexample at (depth 1, b0 1, opCount 0): C `0x202901`, L `0x400001` |
| L flag-on empty stack returns `CELL_CONT` instead of 18 | counterexample at depth 0: C `0x200048`, L `0x200001` |

The second mutant is the interesting one: it shows the op-count field of the
observable is genuinely part of the checked equality, not decoration.  The
third pins the contrast itself, so the flag-on/depth-0 row is not a
self-satisfying sentinel agreement.  No mutant is committed.

## L-leg provenance

`src/l_leaf.cpp` transliterates `Defs.lean:817-848` (`stepBody`: the op-count
bump precedes dispatch) and `Defs.lean:857-875` (`dispatchOp` wires 0xb1/0xb2).
The mapping is in `src/lean_excerpt.md`.

It is **not** generated twin output.  `twin/ops_ir.py` OP_CLTV/OP_CSV emit

```python
if (!ctx.flags.cltv) return TWIN_OK;
return TWIN_INVALID_UNSUPPORTED;
```

so the twin has the flag-off branch but declares the flag-on path unsupported
(a capability boundary, F-LOCKTIME-001).  The flag-off branch is textually the
same `.ok st`, so the twin agrees on the row; the contrast has to come from
the Lean model of record.

## Boundary, stated plainly

Flag-on **with a non-empty stack** is not modelled: both legs return the
declared boundary code 3.  That region is
`decodeNum`/`CheckLockTime`/`CheckSequence`, which needs the transaction
context and is proved in `locktime/C-L-cltv-op` (SCR-122..125) and
`locktime/C-L-csv-op` (SCR-126..129).  The contrast this cell needs — the guard
becoming reachable — lives entirely at depth 0, where both legs execute real
source text.  No row is claimed twice.

## Certificate notes

Both tool certificates hash only tracked cell inputs plus
`contract/error_kind.h` and the raw `result.txt`.  `src/build.sh` drops the
` or disjoint ` poison flag from the extracted `.ll` before reassembly (SAW 1.6
leaves that flag unconstrained; the packed fields are bit-disjoint by
construction), and both tools consume the same normalized artifact.
