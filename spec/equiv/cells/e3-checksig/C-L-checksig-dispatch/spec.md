# Cell `e3-checksig/C-L-checksig-dispatch`

## What is proved

Three closed witness functions per leg, compared with Alive2 and verified
against oracle-derived packed constants with SAW:

| Function | Checker | Expected packed | Meaning |
|---|---|---|---|
| `cell_checksig` | 0 | `0x108` | CHECKSIG pushes false; script ends EVAL_FALSE(2), depth 1, `{}` |
| `cell_checksig` | 1 | `0x2901` | CHECKSIG pushes `{1}`; pass |
| `cell_checksigverify` | 0 | `0x38` | CHECKSIGVERIFY returns ordinal 14 |
| `cell_checksigverify` | 1 | `0x2901` | verify succeeds, harness OP_1 passes |
| `cell_checksig_underflow` | — | `0x48` | one-element stack returns ordinal 18 |

Alive2 quantifies over the checker verdict (the external call); SAW pins it to
0 and 1 in two builds. The `0x2901` encoding is result=1, error=0, depth=1,
top=(len=1,val=1). The exact comparisons are in `alive2/result.txt` and
`saw/result.txt`; certificate hashes cover sources, IR, and outputs.

## SCR coverage is partial

- **SCR-109** ("OP_CHECKSIG pushes FALSE on ∅ sig") is **not assigned to this
  cell**: its signature is the non-empty byte `0x41`. The cell proves the
  push-false-and-continue mechanism for a checker-false verdict, including
  `vchFalse = {}`, but not that an empty `sig` makes the real ECDSA checker
  return false. The narrow `checksig/C-L-checksig-empty` fallback attempts the
  empty-signature arm; SCR-109 remains a gap.
- **SCR-112** ("invalid pubkey makes CHECKSIG push false and continue under
  block flags"): the cell proves the verdict passthrough and that CHECKSIG
  does not abort, conditional on the checker returning false. Pubkey
  validity/encoding and the STRICTENC/WITNESS_PUBKEYTYPE policy arms are not
  modeled.
- Not covered at all: SCR-113 (sigop/OP_COUNT accounting), SCR-102/104/105
  (DER/LOW_S/hashtype policy), SCR-098/099/100/101 (FindAndDelete,
  CONST_SCRIPTCODE, CODESEPARATOR, legacy sighash scriptCode stripping),
  SCR-110 (NULLFAIL), SCR-111 (hashtype passthrough), tapscript CHECKSIGADD.
  These need their own cells or a filed gap.

## Directions

`alive2/result.txt` compares `c_*.ll` (source) with `l_*.ll` (target), and
the harness run records `L ⊑ C`. `run_alive2.sh` executes `alive-tv C L`;
Alive2's transformation check includes the reverse refinement of the return
value for these total functions, and `behavior/` compares both legs on the
same oracle constants. No whole-entry or R claim is made.
