## Build and harness

- clang: `/usr/bin/clang++-20 -std=c++17 -O1 -fno-strict-aliasing
  -fno-discard-value-names -c -emit-llvm`; `llvm-extract --func=<root>
  --recursive` for each root (`_tools/build_leaf.sh`).
- Alive2: `/opt/equiv-tools/alive-tv-v20.0` (v20.0, LLVM 20.1.2).
- SAW: `/opt/equiv-tools/saw-1.6/bin/saw` (1.6, 68eed5f), solver `abc`.
- `_tools/policy_common.h` supplies the flag masks, mainnet buried heights and
  exception classes; it is cell harness, not engine code.
- Roots take only `uint64_t` (or no) arguments, so Alive2 can compare the two
  modules by name and SAW needs no memory model.

## Design

- `c_cell.cpp` is a source excerpt of `GetBlockScriptFlags`
  (validation.cpp:2249-2284) plus the two `policy.h` words, with the exact
  line citations in its header.  It is not the whole validator and it does
  not execute EvalScript.
- `l_cell.cpp` is a **reviewed transliteration** of
  `spec/core/Bitcoin/Activation/Flags.lean` (`mainnetExceptionMap`,
  `buriedActive`, `getBlockScriptFlagsP`, `flagBits`, `consensusFullFlags`)
  and of `PDW93b.standardPolicy`; it is not generated by `twin/ops_ir.py`.
- The observable of the four source roots is the 64-bit flag word (or its
  policy mask); the rows under test are about which source emits which bit,
  so the word is the right observable.  The two integration roots return the
  shared `ScriptError` ordinal after feeding that block word to the LOW_S
  gate and to the CONST_SCRIPTCODE gates.
- The bounded block input is (exception-map class, 32-bit height).  The
  256-bit hash key is abstracted because TXV-056 proves the mainnet map has
  exactly two entries; every other hash is the same `none` branch.
- The integration roots reuse the canonical DER skeleton and the 0/1
  `found>0` model of the sibling gate cells; they add the source-to-gate
  composition, not a new parser.
- No Core patch, no pin change, no twin change.

## Limits

The source claim is full over the bounded domain (3 classes x 2^32 heights).
The hash key is not symbolic, non-mainnet params are out of scope, and the
four deployments modelled are the buried ones.  The cell does not restate or
extend the interpreter gates; it cites the sibling cells for those.

## Why this cell exists

The wave-16 gate cells prove what happens when LOW_S / CONST_SCRIPTCODE is
set, but not the catalogue claim that the block selector never sets them.
`tools/ordering_mutant.out` records a negative check: a C module that ORs the
buried flags before the exception replacement is rejected by Alive2 against
the L module, so the proof is sensitive to Core's order at :2259-2282.
