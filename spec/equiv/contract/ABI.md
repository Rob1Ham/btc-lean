# Harness contract (normative) — ABI v2

Everything in `spec/equiv` is relative to this contract. A proof is only as
strong as the contract, so changes here are versioned and hashed.

**ABI version:** 2 (`EQUIV_ABI_VERSION` in `contract/error_kind.h`).
**Companions:** `contract/tape.md` (tape and domain, normative),
`contract/error_enum.md` (taxonomy, normative). If this file and a companion
disagree, this file wins for the *signature* and the companions win for the
*taxonomy and tape details*; either way, the mismatch is a defect to fix, not
to exploit.

## 1. Entry points (identical in all three shims)

```c
/* Normative, proof-bearing symbol. `error_kind` MUST be non-NULL. */
extern "C" int equiv_entry(
    const uint8_t *tx_bytes, uint64_t tx_len,   /* serialized tx, TX_WITH_WITNESS */
    const uint8_t *spk,      uint64_t spk_len,  /* scriptPubKey, raw bytes */
    int64_t amount,                              /* value of the spent output */
    uint32_t input_index,                        /* input being verified */
    uint64_t flags,                              /* Core script-verify flag bits */
    equiv_error_kind *error_kind);               /* out: shared taxonomy */

/* Non-normative convenience wrapper; discards the kind. */
extern "C" int entry(
    const uint8_t *tx_bytes, uint64_t tx_len,
    const uint8_t *spk,      uint64_t spk_len,
    int64_t amount, uint32_t input_index, uint64_t flags);
```

The wrapper exists because early tooling used the 7-argument form; it is not
proof-bearing. Cells and gates call `equiv_entry`. A shim tolerating a NULL
`error_kind` is defensive only; no gate may rely on it.

## 2. Result codes

| Code | Meaning |
|---:|---|
| 0 | script fails (consensus rejection) |
| 1 | script passes |
| 2 | bad input (out of contract domain; see §5) |
| 3 | internal error / exception / panic |

`error_kind` is written on every `equiv_entry` return:

| Result | `error_kind` |
|---:|---|
| 1 | `EQUIV_ERR_OK` |
| 0 | the Core `ScriptError` ordinal |
| 2 or 3 | `EQUIV_ERR_UNKNOWN_ERROR` |

## 3. Error enum discipline

The shared enum is **Core's `ScriptError` at the pin, 1:1**, including
`EQUIV_ERR_COUNT = 55`. There is no translation table in the Core shim. The
full 56-row mapping, the message strings, and the disposition of older
contract names that do not exist at the pin (`SCRIPTNUM_OVERFLOW`,
`DIV_BY_ZERO`, `SIG_BADLENGTH`, …) are in `contract/error_enum.md`.
`contract/error_kind.h` is generated by `contract/extract_error_enum.py`.

The twin and rbitcoin map their failure reason onto exactly one shared value.
An unmapped failure is `EQUIV_ERR_UNKNOWN_ERROR` **plus a finding**; it is
never silently renamed. Error *precedence* is observable: a cell asserts the
exact value Core reaches first, not "any plausible error".

## 4. Tape format

`tx_bytes` is Bitcoin Core's `TX_WITH_WITNESS` serialization at the pin;
witness data for `input_index` is inside `tx_bytes`, not a separate channel.
`spk` is the raw scriptPubKey (no length prefix). The spent-output convention
is:

```
spent_outputs[i] = (amount, spk)  if i == input_index
                   (0, empty)     otherwise
```

This is exact for base, witness-v0, and single-input taproot; for multi-input
taproot it is a harness convention (BIP341 hashes all spent outputs). Cells
that need genuine multi-input taproot semantics are out of contract and must
be filed as a gap, never silently claimed. Full encoding and edge rules:
`contract/tape.md` §2–§6.

## 5. Domain rules

An input is **in domain** iff:

1. `tx_len > 0`, `tx_bytes != NULL`, and `spk_len == 0 || spk != NULL`;
2. `tx_bytes` decodes as `TX_WITH_WITNESS` with **no trailing bytes**;
3. `input_index < tx.vin.size()`;
4. `0 <= amount <= MAX_MONEY` (2,100,000,000,000,000);
5. `flags & ~0x1fffff == 0` (bits 0..20 only);
6. `WITNESS ⇒ P2SH` and `CLEANSTACK ⇒ P2SH ∧ WITNESS`.

Out of domain returns **2**; a shim must not abort, throw, or return a
pass/fail verdict for it. Cells may restrict the domain further only with an
explicit precondition recorded in the cell. Behavior on result 2/3 is part of
the contract, not "don't care".

## 6. Shims

- No engine logic; marshal only (§ `shims/README.md`).
- No cross-ABI structs; pointers + lengths only. Caller owns all buffers.
- C++ shims catch all exceptions at the boundary (result 3); the Rust shim
  keeps `catch_unwind` and never lets a panic cross `extern "C"`.
- Each shim is line-reviewed and listed in the trust base (`README.md` §11).
- Core is used unmodified unless a patch is registered under
  `patches/README.md`; a patched build is a distinct artifact with its own
  hashes and differential evidence.

## 7. Determinism

For fixed inputs and flags, each leg is a pure function of the tape. Any
dependence on time, environment, locale, allocator state, or thread
scheduling is a contract violation. (rbitcoin's public tx-level entry runs on
a worker pool; cells use the single-input engine function, not that wrapper.)

## 8. Versioning and contract hash

A change to this file, `tape.md`, `error_enum.md`, or `error_kind.h` is a new
contract version and invalidates existing cell records. The hash recipe and
the current contract hash are recorded in `contract/tape.md` §10. Cell records
cite the contract hash they were judged under.
