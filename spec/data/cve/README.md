# spec/data/cve — historical CVE replay vectors

Replay vectors for historical Bitcoin consensus CVEs, run by
`python3 spec/scripts/audit/cve_replay.py` (two tiers: Python mirror via
`scripts/runners/codegen.py`, and the live Lean backends via the generated
module `spec/runners/Test/Audit/CveReplayGen.lean` + driver
`spec/runners/Test/Audit/CveReplay.lean`).

| CVE | year | class | expected rule | tier status |
|---|---|---|---|---|
| CVE-2010-5139 | 2010 | output-value overflow (184B BTC, block 74638) | INV-005/TXV-005 (+INV-006/TXV-006) | REJECTED correctly (lean + python) |
| CVE-2012-2459 | 2012 | merkle-tree mutation (duplicate-tail block) | INV-081/INV-082 | python REPLAYED (root-equality + mutated flag); Lean REPLAYED at block level (4 mined blocks in `cve-2012-2459/`; the residual BLK-011 gap is documented in the findings record) |
| CVE-2018-17144 | 2018 | duplicate-input inflation | INV-007/TXV-007 | REJECTED correctly (lean + python) |

Provenance per file. Block 74638's malformed chain was orphaned by the
post-incident reorg, so CVE-2010-5139 is SYNTHETIC-RECONSTRUCTED from the
public record (output values + the live-fetched coinbase outpoint);
CVE-2018-17144 duplicates the input of a live-fetched mainnet tx.

Vectors are hand-curated data, NOT generated by
`scripts/runners/codegen.py` (which owns `spec/vectors/core`).
